# tsukiko

Локальная расшифровка аудио и диктовка на macOS и Windows. Поддерживаются
Whisper.cpp и NeMo-Speech.cpp; звук и текст не покидают компьютер.

Оба движка едут внутри приложения — ставить отдельно ничего не нужно.
Для Whisper очередь использует `whisper-cli`, а диктовка —
`whisper-server`; NeMo работает через `nemo-speech`. Готовые GGUF-модели
Nemotron и Parakeet запускаются нативно, без Python и NeMo Framework.

Почему свой, а не системный: мы передаём модели флаги, которых в старых
сборках нет вовсе (`--vad`, `-mc`, `--carry-initial-prompt`), а какая
сборка стоит у человека — неизвестно. Свой к тому же не пропадает, если
снести Homebrew. Системный остаётся запасным путём — им приложение
воспользуется, если своего почему-то не оказалось, и в инспекторе
честно напишет, на чьём движке работает. Чужой whisper.cpp tsukiko
не ставит, не правит и не удаляет.

## Скилл для нейросетевых агентов

Внутри приложения едет `tsukiko-transcribe` — расшифровка одной командой,
без окна: агент, которому прислали голосовое, может расшифровать его сам.

```sh
/Applications/tsukiko.app/Contents/Helpers/tsukiko-transcribe запись.ogg
```

Чтобы агент догадался это сделать, ему нужен скилл. Ставится кнопкой:
настройки → «Приложение» → «Скилл для нейросетей». Приложение найдёт
установленных агентов (Claude Code, Codex, Antigravity, OpenClaw, Hermes,
OpenCode) и положит скилл только им.

Сам скилл лежит в `skills/tsukiko/` — его можно поставить и руками,
см. `skills/tsukiko/README.md`.

## Сборка

```sh
./tool/engine.sh          # один раз: собрать движок (нужен brew install cmake)
flutter build macos --release
./tool/sign.sh            # кладёт движок внутрь и подписывает
```

`tool/engine.sh` готовит оба нативных движка. Whisper.cpp собирается из
закреплённых исходников с патчами приложения. NeMo-Speech.cpp берётся из
официальных архивов NVIDIA с проверкой SHA-256: Metal для Apple Silicon,
CPU для Intel, затем Mach-O файлы объединяются в universal. Python
готовому приложению не нужен — только конвертеру нестандартных checkpoint.
Собранное лежит в `macos/Engine` и в репозиторий не попадает.

Патч один и касается только расшифровщика: он отпускает память из-под
сырого звука, как только посчитан мел, — на часовой записи это 2374 МБ
вместо 2645. Текст не меняется ни на слово, объяснение и замеры —
в шапке самого патча и в `docs/задача-память-расшифровщика.md`.

Подпись обязательна: macOS привязывает выданные разрешения к ней, а ad-hoc
подпись Flutter меняется с каждой сборкой — «Универсальный доступ»
пришлось бы выдавать заново после каждой.

Для повседневной работы копируйте собранное в `/Applications`, а не
запускайте из папки сборки: `build/` сносит `flutter clean`, а вместе с
ним пропадает и приложение, которому выдано разрешение.

## Первый запуск на чужом Mac

Приложение подписано, но не нотаризовано у Apple — для нотаризации нужно
платное участие в Apple Developer Program. Поэтому при первом запуске
macOS его задержит: «не удалось проверить разработчика».

Это не поломка и не тупик. Открывается так:

1. **Системные настройки → Конфиденциальность и безопасность**,
   пролистать до раздела «Безопасность»;
2. рядом с именем приложения — **«Открыть всё равно»**, подтвердить
   и ввести пароль администратора;
3. запустить снова.

Один раз, дальше открывается обычным двойным щелчком.

Прежний способ — щелчок правой кнопкой и «Открыть» — в macOS 15 и новее
не работает: Apple его убрала. Кто не хочет ходить в настройки, может
снять карантинную метку в терминале:

```sh
xattr -d com.apple.quarantine /Applications/tsukiko.app
```

**Перетащить в «Программы» обязательно.** Приложение, запущенное из
папки загрузок, macOS переносит в случайное место (app translocation),
и выданный «Универсальный доступ» слетает при каждом запуске.

## Разрешения

Нужно одно: **Универсальный доступ**. Им живёт и перехват клавиш, и
вставка текста в активное окно. «Мониторинг ввода» не нужен: tsukiko
поглощает своё сочетание клавиш, а такому перехвату macOS даёт добро
только по «Универсальному доступу» — проверено, с ним одним всё работает.

В списке «Универсального доступа» tsukiko появляется сам, выключенным:
для этого хватает обращения к системе, окно с вопросом для этого не
нужно. Остаётся щёлкнуть переключатель. Сам по себе tsukiko ничего не
спрашивает — диалог показывается только по кнопке «Запросить» в панели
у строки меню, там же он говорит, если разрешения нет, и открывает
нужный раздел настроек системы. Перезапускать приложение после выдачи
не нужно.

## Настройки

⌘, открывает окно настроек: диктовка, модели, библиотека, общие. Без
значка в Dock у приложения нет строки меню — тогда настройки открываются
из панели у строки меню, кнопкой «Настройки диктовки…». В инспекторе
главного окна остаются настройки распознавания записи: их осмысленно
менять от файла к файлу.

## Расшифровка снаружи

Внутри приложения едет `tsukiko-transcribe` — программа командной строки
без интерфейса. Запускать приложение для неё не нужно: она выбирает
Whisper.cpp или NeMo-Speech.cpp по файлу модели, берёт те же настройки
и печатает текст в stdout.

```sh
/Applications/tsukiko.app/Contents/Helpers/tsukiko-transcribe запись.ogg
/Applications/tsukiko.app/Contents/Helpers/tsukiko-transcribe --status
```

Если tsukiko в это время работает и в настройках включено местное API,
расшифровка уходит в его очередь — так вторая модель не попадает
в память, а текст ложится в библиотеку. Само API живёт на
`127.0.0.1:8756`, выключено по умолчанию и требует ключа; разбор —
в [docs/задача-расшифровка-снаружи.md](docs/задача-расшифровка-снаружи.md).

В `skills/tsukiko/` лежит скилл для нейросетевых агентов: с ним агент
сам догадывается расшифровать присланное голосовое, вместо «извините,
я не могу это прослушать». Куда его класть в Claude Code, Codex,
Antigravity, OpenClaw и Hermes — в `skills/tsukiko/README.md`.

## Разработка

```sh
flutter analyze
flutter test
```

Тесты трогают настоящую систему: запускают `afconvert`, поднимают
`whisper-server`, читают папку данных приложения. Без установленного
whisper.cpp часть из них просто нечего будет проверять.

Устройство приложения, границы систем и план порта на Windows —
в [docs/архитектура.md](docs/архитектура.md). Разобранные задачи с
замерами лежат там же, рядом.

`tool/probe.dart` — ручная проверка детектора занятости модели:
запустите рядом любое распознавание и смотрите, ловит ли его tsukiko.
