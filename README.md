# tsukiko

Расшифровка аудио и диктовка на macOS. Всё считается локально, whisper.cpp.

Движок whisper.cpp едет внутри приложения — ставить отдельно ничего не
нужно. Расшифровка очереди идёт через `whisper-cli`, диктовка — через
`whisper-server`; оба лежат в `Contents/Helpers` под своими именами,
`tsukiko-recognizer` и `tsukiko-dictation`, — под ними их и видно
в «Мониторинге системы».

Почему свой, а не системный: мы передаём модели флаги, которых в старых
сборках нет вовсе (`--vad`, `-mc`, `--carry-initial-prompt`), а какая
сборка стоит у человека — неизвестно. Свой к тому же не пропадает, если
снести Homebrew. Системный остаётся запасным путём — им приложение
воспользуется, если своего почему-то не оказалось, и в инспекторе
честно напишет, на чьём движке работает. Чужой whisper.cpp tsukiko
не ставит, не правит и не удаляет.

## Сборка

```sh
./tool/engine.sh          # один раз: собрать движок (нужен brew install cmake)
flutter build macos --release
./tool/sign.sh            # кладёт движок внутрь и подписывает
```

`tool/engine.sh` качает исходники whisper.cpp закреплённой версии,
сверяет их по sha256, накладывает `tool/recognizer-pcm.patch` и собирает
два самодостаточных универсальных бинарника: статически, с вшитыми
шейдерами Metal, так что рядом с ними не нужно ни библиотек, ни правки
путей загрузки. Собранное лежит в `macos/Engine` и в репозиторий
не попадает.

Патч один и касается только расшифровщика: он отпускает память из-под
сырого звука, как только посчитан мел, — на часовой записи это 2374 МБ
вместо 2645. Текст не меняется ни на слово, объяснение и замеры —
в шапке самого патча и в `docs/задача-память-расшифровщика.md`.

Подпись обязательна: macOS привязывает выданные разрешения к ней, а ad-hoc
подпись Flutter меняется с каждой сборкой — «Универсальный доступ»
пришлось бы выдавать заново после каждой.

Для повседневной работы копируйте собранное в `/Applications`, а не
запускайте из папки сборки: `build/` сносит `flutter clean`, а вместе с
ним пропадает и приложение, которому выдано разрешение.

## Разрешения

Нужно одно: **Универсальный доступ**. Им живёт и перехват клавиш, и
вставка текста в активное окно. «Мониторинг ввода» не нужен: tsukiko
поглощает своё сочетание клавиш, а такому перехвату macOS даёт добро
только по «Универсальному доступу» — проверено, с ним одним всё работает.

В списке «Универсального доступа» tsukiko появляется сам, выключенным:
для этого хватает обращения к системе, окно с вопросом для этого не
нужно. Остаётся щёлкнуть переключатель. Сам по себе tsukiko ничего не
спрашивает — диалог показывается только по кнопке «Запросить» в панели
у строки меню, там же он говорит, если разрешения нет, и открывает
нужный раздел настроек системы. Перезапускать приложение после выдачи
не нужно.

## Настройки

⌘, открывает окно настроек: диктовка, модели, библиотека, общие. Без
значка в Dock у приложения нет строки меню — тогда настройки открываются
из панели у строки меню, кнопкой «Настройки диктовки…». В инспекторе
главного окна остаются настройки распознавания записи: их осмысленно
менять от файла к файлу.

## Разработка

```sh
flutter analyze
flutter test
```

Тесты трогают настоящую систему: запускают `afconvert`, поднимают
`whisper-server`, читают папку данных приложения. Без установленного
whisper.cpp часть из них просто нечего будет проверять.

Устройство приложения, границы систем и план порта на Windows —
в [docs/архитектура.md](docs/архитектура.md). Разобранные задачи с
замерами лежат там же, рядом.

`tool/probe.dart` — ручная проверка детектора занятости модели:
запустите рядом любое распознавание и смотрите, ловит ли его tsukiko.
