# Сборка и выпуск

Как собрать tsukiko под обе системы, что для этого нужно поставить,
что можно **не** ставить, и как выпускать обновления.

Всё, что описано ниже, делается двумя-тремя командами. Длинный текст —
это объяснения, а не работа.

---

## Коротко

| | macOS | Windows |
|---|---|---|
| движок | `./tool/engine.sh` | `tool\engine-win.ps1` |
| звук | системный `afconvert` | ffmpeg — **пока кладётся руками**, см. ниже |
| приложение | `flutter build macos --release` | `flutter build windows --release` |
| подпись | `./tool/sign.sh` | — (подпись установщика по желанию) |
| раздача | `./tool/dmg.sh` → `build/tsukiko.dmg` | `tool\package-win.ps1` → `tsukiko-setup.exe` |

---

## Что поставить на машину сборщика

### macOS

| | зачем | сколько весит |
|---|---|---|
| Xcode + Command Line Tools | компилятор, `codesign`, `tiffutil` | ~10 ГБ |
| Flutter SDK | само приложение | ~3 ГБ |
| `brew install cmake` | сборка движка whisper.cpp | ~120 МБ |
| сертификат разработчика | подпись, к которой привязано разрешение | — |

**Не нужно:** `brew install whisper-cpp` — движок собирается свой
и едет внутри приложения. Vulkan SDK не нужен: на macOS ускоряет Metal,
и он в системе.

Для перерисовки фона образа (`tool/dmg-background.py`) нужны `rsvg-convert`
(`brew install librsvg`) и Pillow (`pip3 install pillow`). Нужны они
ровно один раз: готовый фон лежит в `design/dmg-background.tiff`
и в репозитории.

### Windows

| | зачем | сколько весит |
|---|---|---|
| Visual Studio 2022, «Разработка классических приложений на C++» | компилятор MSVC | ~7 ГБ |
| Flutter SDK | само приложение | ~3 ГБ |
| CMake | сборка движка (входит в состав Visual Studio) | — |
| Vulkan SDK | компилятор шейдеров `glslc` для Vulkan-сборки движка | ~250 МБ |
| Inno Setup 6 | установщик | ~20 МБ |

**Не нужно:**

* **CUDA Toolkit — не нужен вовсе.** Ускоряет Vulkan, и он работает
  на NVIDIA не хуже, а заодно на AMD и Intel. Официальная сборка
  whisper.cpp с CUDA весит 640 МБ против 8 МБ процессорной — это вес
  библиотек, которые пришлось бы возить с собой ради одного
  производителя видеокарт. Мы их не возим.
* **Vulkan SDK на машине пользователя — не нужен.** Он нужен только
  при сборке: шейдеры компилируются в SPIR-V и вшиваются в бинарник.
  На машине пользователя нужен лишь загрузчик `vulkan-1.dll`, а его
  кладут драйверы видеокарты.
* **vcredist — не нужен.** Движок собирается со статическим
  C-рантаймом (`/MT`).
* **Полный ffmpeg — не нужен.** Хватает урезанного: только
  аудиодекодеры, строго LGPL, без GPL-кодеков.

Если Vulkan SDK ставить не хочется, соберите одну процессорную сборку:
приложение подхватит `-cpu.exe` и будет работать, просто медленнее.

## Как собирается движок

Один и тот же whisper.cpp закреплённой версии (v1.9.3), архив сверяется
по sha256, поверх накладывается `tool/recognizer-pcm.patch` (он
освобождает память сразу после расчёта спектрограммы).

**macOS** — одна сборка на все машины: статическая, универсальная
(`arm64;x86_64`), с вшитыми шейдерами Metal. Кладётся в
`Contents/Helpers` под именами `tsukiko-recognizer` и
`tsukiko-dictation`.

**Windows** — две сборки:

| | когда берётся |
|---|---|
| `tsukiko-recognizer-vulkan.exe` | в системе есть `vulkan-1.dll` |
| `tsukiko-recognizer-cpu.exe` | загрузчика Vulkan нет |

Выбирает приложение само, при запуске (`os.engineNames`). Почему две,
а не одна: нет видеокарты — не беда, Vulkan-сборка ловит своё исключение
и считает на процессоре; а вот нет `vulkan-1.dll` — Windows убивает
процесс на запуске, до первой строки кода. Подробнее —
в `docs/задача-свой-движок.md`.

## Расшифровщик из командной строки

`tsukiko-transcribe` собирается отдельно от приложения и Flutter в себя
не берёт:

```sh
dart compile exe bin/tsukiko_transcribe.dart -o tsukiko-transcribe
```

Отдельно звать это не нужно — `tool/sign.sh` и `tool/package-win.ps1`
делают это сами и кладут результат туда, где программа найдёт движок:
на macOS в `Contents/Helpers` рядом с ним, на Windows — рядом
с `tsukiko.exe`. Установщик Inno Setup забирает релизную папку целиком,
поэтому в `installer.iss` править нечего.

Сборка займёт секунды. Если она вдруг ругается на `package:flutter` —
значит в `lib/core` или в границу системы втащили подписи; они живут
в `lib/core/labels.dart`, и почему — в
`docs/задача-расшифровка-снаружи.md`.

## Раздача

### macOS: dmg с перетаскиванием

```sh
flutter build macos --release
./tool/sign.sh          # кладёт движок внутрь и подписывает
./tool/dmg.sh           # build/tsukiko.dmg
```

Образ открывается окном 600×400: слева приложение, справа «Программы»,
между ними стрелка. Фон — `design/dmg-background.tiff`, многостраничный
TIFF на два разрешения (обычное и Retina): Finder сам берёт нужное,
отдельного файла «@2x» рядом он не ищет.

Фон нарисован средним тоном намеренно. Finder подписывает значки цветом
темы — чёрным в светлой, белым в тёмной, — а картинка в образе одна
на обе. На светлом фоне белая подпись пропадает, на тёмном чёрная.
Выбранный тон даёт контраст 5,0 с чёрным и 4,2 с белым: читаются оба.

Перерисовать фон: `python3 tool/dmg-background.py`. Координаты гнёзд
на картинке и координаты значков в `tool/dmg.sh` — одни и те же числа
(150,190) и (450,190); правите одно — правьте и другое.

Перетаскивание в «Программы» — не украшение. Приложение, запущенное
из папки загрузок, macOS переносит в случайное место (app translocation),
и выданный ему «Универсальный доступ» перестаёт действовать при каждом
запуске. Без переезда в «Программы» диктовка просто не работает.

### Windows: установщик

```powershell
tool\engine-win.ps1
tool\build-ffmpeg-win.ps1   # проверяет, что ffmpeg.exe на месте
tool\package-win.ps1        # build\installer\tsukiko-setup.exe
```

### Сборка на GitHub, без своей машины с Windows

`.github/workflows/windows.yml` собирает всё то же самое на раннере
GitHub — на каждый пуш в `main` и по кнопке. Ради этого он и заведён:
проверить, что нативная часть вообще компилируется, иначе негде.

Что там происходит: ставится Flutter, качается Vulkan SDK (тихой
установкой LunarG — тот же рецепт, что у CI самого llama.cpp), собирается
движок, потом приложение, `tsukiko-transcribe` и тесты. Собранная папка
уходит в артефакты: скачал, распаковал, запустил на настоящей Windows.

Visual Studio и CMake на раннере уже есть, Inno Setup — нет, он ставится
через choco и только когда дело доходит до установщика.

Движок кладётся в кэш по `tool/engine-win.ps1` и `tool/recognizer-pcm.patch`:
в них лежит и версия, и всё, что на неё влияет. Первая сборка — минут
двадцать (две конфигурации, долгие шейдеры Vulkan), дальше около пяти,
пока версия движка не поменяется.

Чего CI не заменит: он ничего не запускает. Встаёт ли панель у значка,
работает ли двойной стук, отменяет ли лишняя клавиша начатую запись —
только руками, на скачанной сборке. И подписи там нет: без сертификата
установщик выйдет неподписанным, и SmartScreen будет ругаться. Для
проверки годится, для раздачи — нет.

Установщик в CI собирается только если в `windows/Engine` лежит
`ffmpeg.exe` (см. ниже). Нет его — работа не падает, просто вместо
установщика в артефактах одна папка и предупреждение в журнале.

### Про ffmpeg на Windows: шаг пока ручной

`tool\build-ffmpeg-win.ps1` **не собирает** ffmpeg сам. Он кладёт рядом
текст лицензии, печатает готовые флаги `configure` и проверяет, что
`windows\Engine\ffmpeg.exe` на месте; нет — останавливает сборку
с объяснением. Раньше он молчал, и установщик собирался без декодера:
на такой сборке m4a и opus не расшифровывались вовсе, а понять почему
было нельзя.

Что делает декодер: `whisper` сам читает wav, mp3, flac и ogg. Всё
остальное — m4a с диктофона, голосовые из мессенджеров, дорожки
из видео — надо переложить в WAV, и на macOS это делает системный
`afconvert`, а на Windows системного конвертера нет.

Собрать его нужно один раз, в MSYS2, по флагам из скрипта
(`-BuildFromSource` их печатает). Важно: **без** `--enable-gpl`
и `--enable-nonfree` — иначе лицензия перестанет позволять класть
его внутрь приложения.

Установщик Inno Setup ставится в профиль пользователя
(`%LOCALAPPDATA%\Programs\tsukiko`) и **не просит прав администратора**.
Рядом кладётся `tsukiko-portable.zip` — та же папка без установщика.

## Обновления

Своего самообновления нет намеренно. Оно потребовало бы кода, который
сам скачивает и сам подменяет исполняемый файл, — а такому коду нужно
доверять больше, чем всему остальному приложению вместе взятому.
Выигрыш — два щелчка.

Как устроено вместо этого: «О программе» → «Проверить обновления».
Приложение спрашивает последний выпуск на GitHub, сравнивает версии
числами (не строками: «1.10.0» новее «1.9.0», хотя как строка меньше)
и, если вышло новее, отводит на страницу выпуска. Ни сети, ни ответа,
чужой ответ — значит новостей нет: это не тот повод, чтобы беспокоить
человека сообщением об ошибке.

### Как выпустить новую версию

1. Поднять версию **в двух местах**: `version:` в `pubspec.yaml`
   и `appVersion` в `lib/platform/os.dart`. Они обязаны совпадать —
   вторую читает проверка обновлений. Установщик Windows свою копию
   не держит: `tool\package-win.ps1` читает версию из pubspec и передаёт
   её Inno Setup ключом.
2. Собрать обе системы (команды выше).
3. Создать выпуск на GitHub с меткой `v1.0.1` и приложить
   `tsukiko.dmg` и `tsukiko-setup.exe`. Текст выпуска попадёт
   в окно обновления как есть.
4. Проверить: в старой сборке «Проверить обновления» должно найти новую.

Обновление ставится **поверх** прежнего:

* macOS — перетащить из образа в «Программы», заменив;
* Windows — запустить установщик, он обновит на месте.

Настройки, скачанные модели и незаконченная работа лежат отдельно
(`~/Library/Application Support/app.yuko.tsukiko`,
`%APPDATA%\app.yuko.tsukiko`) и переезд переживают.

Одно исключение на macOS: подпись должна остаться той же. Разрешение
«Универсальный доступ» macOS привязывает к ней, и сборка, подписанная
другим сертификатом, попросит разрешение заново.

## Чистка

Сборка занимает место, и почти всё его можно вернуть.

```sh
flutter clean                    # ~2-3 ГБ: сборки приложения
rm -rf build/engine              # ~1,5 ГБ: исходники и сборка whisper.cpp
```

Собранный движок (`macos/Engine`, `windows\Engine`, ~15-30 МБ) стоит
оставить: он не меняется от сборки к сборке, а собирается несколько
минут. Скрипты и так пропускают сборку, если он на месте и нужной
версии, — метка лежит в `.version` рядом.

**`flutter clean` сносит `build/` целиком, а с ним и приложение.**
Для повседневной работы держите копию в «Программах», а не запускайте
из папки сборки.
